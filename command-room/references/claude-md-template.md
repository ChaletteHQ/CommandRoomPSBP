# CLAUDE.md Template — Command Room

> **Generated by:** Command Room onboarding skill
> **Purpose:** Cowork loads this file automatically every session. It gives Claude working memory so it knows who you are, what you're juggling, and how you work — without reading a dozen files first.
> **Target:** ≤80 lines INCLUDING the machine-generated blocks. This is a hot cache, not a database — community-measured adherence degrades past ~80 always-loaded lines, so the budget is behavioral, not aesthetic (SPEC STYLE1 step 3b).
> **Substrate note (v3.12.0):** This template references `_hq/MASTER_TRACKER.md` and `_hq/PEOPLE.md` as readable workspace files. Per `references/SOURCE_OF_TRUTH.md`, those are Tier 2 regenerated views (canonical source lives in `_hq/data/entities.json` + `events.jsonl`). For surface decisions that depend on current state, skills overlay events.jsonl on top of the view per the v3.11.4 contract. This template populates only static reference data (project names, people names, terms) — orientation only, never used to determine "what's outstanding."

## Generation Rules

The onboarding skill fills this template as its **final step** after the workspace is scaffolded and populated.

### What populates each section:

| Section | Source | Cap |

### The persona block (machine-owned — never hand-fill):

`LIVE-STATE:persona` is created and maintained by `shared/scripts/render_claude_md.py` AFTER onboarding writes the `chat_persona` store (SPEC STYLE1). It renders ≤8 lines only on workspaces with a configured persona. Do not author it from this template, do not edit inside its markers, and budget for it: the ≤80-line target INCLUDES this block.

### The compressed binding layer (SPEC STYLE1 step 3b, D9 ruling):

The four IMPORTANT bullets above are the compressed form of the EW1 / T2.2 / RSR1 enforcement paragraphs. Three things about them are load-bearing and pinned by tests — do not reword casually:
- Each carries its **idempotency marker phrase** verbatim (`claude_md_email_rule_v1` / `claude_md_widget_rule_v1` / `claude_md_research_rule_v1` / `draft_posture_queue_on_click_v1` in the update bridge detect application by these exact phrases).
- Each keeps **rule language** (never/must/only-when) so `claude_md_guard.is_rule_language` still protects it from cleanup compression.
- Each carries its **why in one clause** — emphasis markers plus a reason measurably improve adherence (STYLE1 research addendum).
Regression cover: `run_email_delegation_rule_test.py`, `run_widget_rule_migration_test.py`, and the step-3b pins in `run_style1_test.py`.

### Line budget (≤80 including the persona block):
- Header + Me: ~4 · Quick Commands: ~3 · Session Rules: ~9 · Preferences: ~5
- People: ~17 (header + 15) · Projects: ~14 · Terms: ~13 · Workspace: ~4

### `{{PROMPT_RESTRUCTURING}}` variable (compressed in STYLE1 step 3b):
Three answer paths from the onboarding calibration question:
- **Yes (dictates/brain-dumps):** `- **Prompt restructuring:** When a long brain-dump lands with multiple asks, restructure to priority order and confirm in one tight sentence before acting — never on short, structured, or factual prompts.`
- **Sometimes:** `- **Prompt restructuring (light):** Only when prompts run long with multiple asks — surface the priority order and confirm before acting on the wrong one.`
- **No:** variable left blank; the line doesn't appear.

### Promotion / Demotion (ongoing maintenance):
- When "end session" runs, check if any new people or terms came up that should be in CLAUDE.md
- If a project moves to Archive, remove from Active Projects table
- If a person hasn't been mentioned in 30+ days, consider demoting (remove from CLAUDE.md, they stay in PEOPLE.md)
- The workspace-manager handles this during "end session" — NOT a separate task the user has to remember. Any hand-section edit binds to the cleanup Rule 12 guard (`claude_md_guard.report`).

### For existing users (update path):
1. The update bridge owns migration: the binding-layer bullets append via their marker-gated migrations; `claude_md_diet_v1` offers the compressed form as a replacement block (announce, never silent — the file is the customer's).
2. If the user has a workspace but no CLAUDE.md (v1.3.x path): read _hq/MASTER_TRACKER.md, _hq/PEOPLE.md, _hq/BUSINESS_CONTEXT.md and auto-generate — no re-interview. Tell the user: "I generated your Command Room quick-reference file. You can edit it anytime."
3. Triggers: "generate my claude file", "build my memory file", "update my claude.md", or automatically on first "let's work" if CLAUDE.md doesn't exist.
